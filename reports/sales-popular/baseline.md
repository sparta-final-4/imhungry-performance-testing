# 인기 특가 부하 테스트: 기준선

상태: 초안 · 측정일: 2026-11-05 · 도메인 담당자: 장준혁

- 근거 자료: 스크립트 [`scenarios/sales-popular/sales-popular.js`](../../scenarios/sales-popular/sales-popular.js), 시드 [`seed-search-clicks.sql`](../../scenarios/sales-popular/seed-search-clicks.sql), 표는 [`tools/summarize.py`](../../tools/summarize.py)로 만들었습니다. 환경과 실행 방법은 [README.md](../../README.md)를 따릅니다. 원본 결과 파일은 저장소에 두지 않습니다.
- 미정 항목: 합격선과 목표 부하, 측정한 앱 커밋 해시와 이 저장소의 커밋 해시.

## 1. 대상

| 항목 | 내용 |
|---|---|
| API | GET /api/sales/popular |
| 화면 | 메인 화면 인기 특가 |
| 로그인 | 필요 없음 |
| 처리 | 진행 중 행사 조회와 최근 7일 검색 클릭 집계(상품별 그룹). 캐시 없음 |

## 2. 측정 조건

- 검색 클릭 이력 97,480건입니다.
- 행사 8개(진행 중 3개, 종료 5개), 행사 상품 8개입니다.
- 앱은 이 API만 호출했습니다.

## 3. 부하 조건

| 항목 | 값 |
|---|---|
| 초당 요청 수 | 0에서 시작해 200 → 500 → 1,000 → 2,000건으로 단계마다 60초 동안 직선으로 올림(첫 단계 평균 100건) |
| 자동 중단 | 못 따라간 요청 20,000건 초과, 또는 누적 p95 2,000ms 초과 |
| 반복 | 3회, 회차 사이 60초 쉼. 먼저 가볍게 돌려 확인 |

각 단계의 숫자는 그 단계 끝에서 도달하는 속도입니다.

## 4. 실행 방법

```bash
./tools/run.sh -e RATES=200,500,1000,2000 scenarios/sales-popular/sales-popular.js
python3 tools/summarize.py --prefix sales-popular --last 3 --steps 200:60,500:60,1000:60,2000:60 --uri /api/sales/popular --method GET
```

## 5. 결과

### 5-1. 회차별 전체 결과

세 회차 모두 시작 약 50초 만에(첫 단계 도중, 이때 보내는 속도는 초당 약 167건) 누적 p95가 2,000ms를 넘어 자동 중단됐습니다. 실패율은 0%입니다. 이 보고서의 값은 모두 중단 전 약 50초 구간에서 나온 것입니다.

| 회차 | p50 | p90 | p95 | p99 | 최대 | 요청 수 | 못 따라간 요청 | 실패율 | 시작 전 부하 평균(1분) |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 16ms | 1,479ms | 2,229ms | 4,042ms | 6,158ms | 3,729 | 430 | 0% | 1.94 |
| 2 | 16ms | 1,558ms | 2,330ms | 3,641ms | 6,784ms | 3,957 | 544 | 0% | 1.34 |
| 3 | 16ms | 1,569ms | 2,376ms | 3,579ms | 5,561ms | 3,969 | 536 | 0% | 1.07 |

모든 회차를 CPU 유휴율 93% 이상인 호스트에서 시작했습니다.

### 5-2. 서버 쪽 지표 (중단 전 구간, 3회 중앙값, 범위는 괄호)

단계 구간은 요청 시작 시각에서 추정해 경계에 ±10초 정도 오차가 있습니다. 자동 중단 뒤의 단계 구간은 요청이 없어 적지 않았습니다.

| 지표 | 중단 전 구간(0 → 약 167건) |
|---|---|
| 앱 처리 속도 평균(건/초) | 69 (64–71) |
| 앱 p95(ms, 구간 최대) | 5,308 (5,141–6,318) |
| 앱 p99(ms, 구간 최대) | 7,019 (6,099–7,944) |
| 커넥션 풀 사용 중(최대 10) | 10 (10–10) |
| 커넥션 풀 기다리는 요청 | 190 (190–191) |
| MySQL 실행 중 스레드 | 12 (12–12) |
| 요청 1건당 SQL 문(트랜잭션 제어 포함) | 26.9 (26.9–27.0) |
| 앱 프로세스 CPU(%) | 1.5 (1.4–1.5) |
| GC 멈춤(시간 중 %) | 0.2 (0.1–0.2) |

요청 1건당 SQL 문은 MySQL이 받은 전체 문장 수를 앱이 받은 요청 수로 나눈 값이라 트랜잭션 시작·종료 문장을 포함합니다.

- 처리 한계는 초당 약 70건 안팎입니다. 50초 동안 평균 약 83건/초를 보냈고(0에서 올리는 중) 완료된 요청은 3,729건(약 75건/초)이었으며, 앱 처리 속도는 69건/초(64–71)에서 더 오르지 않았습니다.
- 커넥션 풀이 가득 차(10/10) 요청이 190건씩 기다렸고, MySQL 실행 중 스레드가 12개로 차 있었습니다. 앱 CPU는 1.5%였습니다.
- 요청 1건당 SQL 문이 약 27개입니다.
