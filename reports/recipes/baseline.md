# 레시피 목록·상세 부하 테스트: 기준선

상태: 초안 · 측정일: 2026-11-05 · 도메인 담당자: 강준모

- 근거 자료: 스크립트 [`scenarios/recipes/recipes.js`](../../scenarios/recipes/recipes.js), 표는 [`tools/summarize.py`](../../tools/summarize.py)로 만들었습니다. 환경과 실행 방법은 [README.md](../../README.md)를 따릅니다. 원본 결과 파일은 저장소에 두지 않습니다.
- 미정 항목: 합격선과 목표 부하, 측정한 앱 커밋 해시와 이 저장소의 커밋 해시.

## 1. 대상

| 항목 | 내용 |
|---|---|
| API | GET /api/recipes (목록, 키워드 목록), GET /api/recipes/{recipeId} (상세) |
| 화면 | 레시피 목록, 레시피 상세 |
| 로그인 | 필요 없음 |
| 호출 비율 | 목록 50%, 키워드 목록 25%, 상세 25% |

## 2. 측정 조건

- 레시피 1,693개입니다(DB 건수와 같음).
- 목록은 페이지 1–3(한 페이지 20개), 키워드는 5개(찌개, 볶음, 국, 계란, 두부) 중 하나, 상세는 목록 API로 받은 레시피 번호 중 하나를 무작위로 골랐습니다.
- 앱은 이 API만 호출했습니다. 캐시는 없습니다.

## 3. 부하 조건

| 항목 | 값 |
|---|---|
| 초당 요청 수 | 0에서 시작해 200 → 500 → 1,000 → 2,000건으로 단계마다 60초 동안 직선으로 올림, 마지막에 10초 동안 0으로 내림(합계 약 172,000건) |
| 자동 중단 | 못 따라간 요청 20,000건 초과, 또는 누적 p95 2,000ms 초과 |
| 반복 | 3회, 회차 사이 60초 쉼. 먼저 가볍게 돌려 확인 |

각 단계의 숫자는 그 단계 끝에서 도달하는 속도입니다. 2,000건 단계는 1,000건에서 2,000건까지 올라가는 60초라 평균은 약 1,500건입니다.

## 4. 실행 방법

```bash
./tools/run.sh -e RATES=200,500,1000,2000 scenarios/recipes/recipes.js
python3 tools/summarize.py --prefix recipes --last 3 --steps 200:60,500:60,1000:60,2000:60 --uri /api/recipes --method GET
```

### 5-2. 단계별 서버 쪽 지표 (3회 중앙값, 범위는 괄호)

이 표는 이 환경에서 관찰한 값입니다. 커넥션 풀·MySQL 스레드·CPU 같은 포화 지표는 환경에 따라 달라 dev의 값으로 쓰지 않습니다.

단계 구간은 요청 시작 시각에서 추정해 경계에 ±10초 정도 오차가 있습니다.

| 지표 | 200건 | 500건 | 1,000건 | 2,000건 |
|---|---|---|---|---|
| 앱 처리 속도 평균(건/초) | 63 (63–65) | 239 (237–242) | 520 (519–527) | 1,052 (1,049–1,053) |
| 앱 p95(ms, 구간 최대) | 8 (8–9) | 2 (2–279) | 2 (2–104) | 2 (2–8) |
| 앱 p99(ms, 구간 최대) | 9 (8–19) | 2 (2–422) | 2 (2–188) | 9 (3–21) |
| 커넥션 풀 사용 중(최대 10) | 1 (0–1) | 1 (1–10) | 1 (1–2) | 2 (1–3) |
| 커넥션 풀 기다리는 요청 | 0 (0–0) | 0 (0–53) | 0 (0–0) | 0 (0–0) |
| MySQL 실행 중 스레드 | 3 (2–3) | 3 (2–3) | 3 (3–3) | 4 (3–4) |
| 요청 1건당 SQL 문(트랜잭션 제어 포함) | 9.7 (9.6–11.2) | 9.7 (9.6–10.4) | 9.9 (9.8–10.4) | 9.7 (9.7–10.4) |
| 앱 프로세스 CPU(%) | 1.5 (1.4–1.7) | 2.9 (2.9–5.0) | 6.0 (5.8–7.8) | 12.8 (12.6–13.3) |
| GC 멈춤(시간 중 %) | 0.1 (0.1–0.1) | 0.2 (0.1–1.7) | 0.5 (0.3–0.9) | 1.1 (1.0–1.4) |

요청 1건당 SQL 문은 MySQL이 받은 전체 문장 수를 앱이 받은 요청 수로 나눈 값이라 트랜잭션 시작·종료 문장을 포함합니다.
앱 프로세스 CPU(%)는 호스트 CPU 10개 기준 비율입니다(10% = 1코어). 서버 컨테이너의 한도는 2코어라서 20%가 한도입니다.

- 2,000건 단계까지 p95 중앙값이 2ms였습니다. 500건 단계에서 한 회차만 p95 279ms가 나왔습니다.
