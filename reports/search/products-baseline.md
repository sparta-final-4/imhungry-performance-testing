# 상품 검색 부하 테스트: 기준선

상태: 초안 · 측정일: 2026-11-04 · 도메인 담당자: 강준모

- 근거 자료: 스크립트 [`scenarios/search/search.js`](../../scenarios/search/search.js)(`TARGET=products`), 표는 [`tools/summarize.py`](../../tools/summarize.py)로 만들었습니다. 환경과 실행 방법은 [README.md](../../README.md)를 따릅니다. 원본 결과 파일은 저장소에 두지 않습니다.
- 미정 항목: 합격선과 목표 부하, 측정한 앱 커밋 해시와 이 저장소의 커밋 해시.

## 1. 대상

| 항목 | 내용 |
|---|---|
| API | GET /api/search/products?keyword=…&page=…&size=20 |
| 화면 | 통합검색 상품 목록 |
| 로그인 | 필요 없음 |

## 2. 측정 조건

- 색인한 상품은 17개(DB 건수와 같음)입니다.
- 검색어는 요청마다 7개(대파, 두부, 계란, 된장, 김치, 삼겹살, 밀키트) 중 하나, 페이지는 1 또는 2를 무작위로 골랐습니다.
- 검색어별 결과 건수는 대파 1, 두부 1, 계란 1, 된장 1, 김치 0, 삼겹살 0, 밀키트 5입니다. 결과가 거의 없는 작은 데이터에서 측정한 값입니다.
- 앱은 검색 외 요청 없이 이 API만 호출했습니다. 캐시는 없습니다.

## 3. 부하 조건

| 항목 | 값 |
|---|---|
| 초당 요청 수 | 200 → 500 → 1,000 → 2,000건, 단계마다 60초 |
| 자동 중단 | 못 따라간 요청 20,000건 초과, 또는 누적 p95 2,000ms 초과 |
| 반복 | 3회, 회차 사이 15초 쉼. 먼저 가볍게 돌려 확인(p95 19.5ms, 실패 0) |

## 4. 실행 방법

```bash
./tools/run.sh -e TARGET=products -e RATES=200,500,1000,2000 scenarios/search/search.js
python3 tools/summarize.py --prefix search --last 3 --steps 200:60,500:60,1000:60,2000:60 --uri /api/search/products --method GET
```

## 5. 결과

### 5-1. 회차별 전체 결과

세 회차 모두 자동 중단됐습니다(회차 1·2는 못 따라간 요청 20,000건 초과, 회차 3은 못 따라간 요청 초과와 p95 2,000ms 초과). 아래 값에는 한계를 넘긴 구간이 섞여 있어서, 개선 전후 비교는 5-2의 단계별 값으로 합니다.

| 회차 | p50 | p90 | p95 | p99 | 최대 | 요청 수 | 못 따라간 요청 | 실패율 | 시작 전 부하 평균 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 5ms | 668ms | 877ms | 1,325ms | 3,764ms | 73,531 | 21,797 | 0% | 3.16 |
| 2 | 131ms | 800ms | 977ms | 1,389ms | 3,418ms | 64,991 | 20,199 | 0% | 9.65 |
| 3 | 28ms | 877ms | 1,123ms | 1,670ms | 4,318ms | 57,925 | 20,401 | 0% | 9.43 |

회차 2·3은 시작 전 부하 평균이 높아 호스트 부하의 영향을 받았을 수 있습니다.

### 5-2. 단계별 서버 쪽 지표 (3회 중앙값, 범위는 괄호)

단계 구간은 요청 시작 시각에서 추정해 경계에 ±10초 정도 오차가 있습니다.

| 지표 | 200건 | 500건 | 1,000건 | 2,000건 |
|---|---|---|---|---|
| 앱 처리 속도 평균(건/초) | 91 (84–93) | 329 (317–331) | 512 (482–624) | 182 (175–197) |
| 앱 p95(ms) | 19 (14–32) | 9 (8–111) | 1,317 (1,263–1,369) | 1,338 (988–1,855) |
| 앱 p99(ms) | 33 (22–69) | 44 (21–213) | 1,843 (1,723–1,987) | 1,797 (1,344–2,620) |
| 커넥션 풀 사용 중(최대 10) | 1 (1–1) | 2 (1–10) | 10 (10–10) | 10 (10–10) |
| 커넥션 풀 기다리는 요청 | 0 (0–0) | 0 (0–36) | 184 (180–186) | 180 (180–187) |
| MySQL 실행 중 스레드 | 3 (2–3) | 3 (3–3) | 3 (2–6) | 3 (2–5) |
| 요청 1건당 SQL 문(트랜잭션 제어 포함) | 12.7 (10.9–12.7) | 11.9 (11.1–12.0) | 11.2 (11.1–12.0) | 12.8 (11.9–14.1) |
| 앱 프로세스 CPU(%) | 3.6 (2.8–4.8) | 9.9 (8.2–17.2) | 20.9 (20.8–21.0) | 21.0 (20.8–21.3) |
| GC 멈춤(시간 중 %) | 2.0 (0.9–4.6) | 1.4 (1.0–2.4) | 4.4 (3.8–5.2) | 4.0 (3.6–4.6) |

요청 1건당 SQL 문은 MySQL이 받은 전체 문장 수를 앱이 받은 요청 수로 나눈 값이라 트랜잭션 시작·종료 문장을 포함합니다.
