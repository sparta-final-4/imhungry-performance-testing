# 레시피 검색 부하 테스트: 기준선

상태: 초안 · 측정일: 2026-11-04 · 도메인 담당자: 강준모

- 근거 자료: 스크립트 [`scenarios/search/search.js`](../../scenarios/search/search.js)(`TARGET=recipes`), 표는 [`tools/summarize.py`](../../tools/summarize.py)로 만들었습니다. 환경과 실행 방법은 [README.md](../../README.md)를 따릅니다. 원본 결과 파일은 저장소에 두지 않습니다.
- 미정 항목: 합격선과 목표 부하, 측정한 앱 커밋 해시와 이 저장소의 커밋 해시.

## 1. 대상

| 항목 | 내용 |
|---|---|
| API | GET /api/search/recipes?keyword=…&page=…&size=20 |
| 화면 | 통합검색 레시피 목록 |
| 로그인 | 필요 없음 |

## 2. 측정 조건

- 색인한 레시피 1,693개(DB 건수와 같음)입니다.
- 검색어는 요청마다 7개(대파, 두부, 계란, 된장, 김치, 삼겹살, 밀키트) 중 하나, 페이지는 1 또는 2를 무작위로 골랐습니다.
- 검색어별 결과 건수는 대파 469, 두부 216, 계란 334, 된장 112, 김치 117, 삼겹살 21, 밀키트 0입니다.
- 앱은 검색 외 요청 없이 이 API만 호출했습니다. 캐시는 없습니다.

## 3. 부하 조건

| 항목 | 값 |
|---|---|
| 초당 요청 수 | 200 → 500 → 1,000 → 2,000건, 단계마다 60초 |
| 자동 중단 | 못 따라간 요청 20,000건 초과, 또는 누적 p95 2,000ms 초과 |
| 반복 | 3회, 회차 사이 15초 쉼. 먼저 가볍게 돌려 확인(p95 26ms, 실패 0) |

초당 요청 수를 정해 보내므로 응답이 느려져도 보내는 양은 같고, 못 따라간 요청이 쌓입니다.

## 4. 실행 방법

```bash
./tools/run.sh -e TARGET=recipes -e RATES=200,500,1000,2000 scenarios/search/search.js
python3 tools/summarize.py --prefix search --last 3 --steps 200:60,500:60,1000:60,2000:60 --uri /api/search/recipes --method GET
```

## 5. 결과

### 5-1. 회차별 전체 결과

세 회차 모두 못 따라간 요청이 20,000건을 넘어 자동 중단됐습니다. 아래 값에는 한계를 넘긴 구간이 섞여 있어서, 개선 전후 비교는 5-2의 단계별 값으로 합니다.

| 회차 | p50 | p90 | p95 | p99 | 최대 | 요청 수 | 못 따라간 요청 | 실패율 | 시작 전 부하 평균 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 3ms | 423ms | 590ms | 861ms | 1,989ms | 101,216 | 20,811 | 0% | 3.13 |
| 2 | 4ms | 652ms | 835ms | 1,191ms | 2,567ms | 74,501 | 20,823 | 0% | 4.61 |
| 3 | 7ms | 745ms | 902ms | 1,294ms | 3,208ms | 69,487 | 20,645 | 0% | 8.03 |

회차 3은 시작 전 부하 평균이 8.03이어서 호스트 부하의 영향을 받았을 수 있습니다.

### 5-2. 단계별 서버 쪽 지표 (3회 중앙값, 범위는 괄호)

단계 구간은 요청 시작 시각에서 추정해 경계에 ±10초 정도 오차가 있습니다.

| 지표 | 200건 | 500건 | 1,000건 | 2,000건 |
|---|---|---|---|---|
| 앱 처리 속도 평균(건/초) | 83 (80–85) | 316 (311–318) | 604 (563–677) | 251 (240–625) |
| 앱 p95(ms) | 12 (12–22) | 4 (4–6) | 930 (441–993) | 1,055 (735–1,193) |
| 앱 p99(ms) | 27 (20–53) | 8 (7–41) | 1,337 (690–1,376) | 1,524 (1,054–1,601) |
| 커넥션 풀 사용 중(최대 10) | 0 (0–1) | 1 (1–1) | 10 (10–10) | 10 (10–10) |
| 커넥션 풀 기다리는 요청 | 0 (0–0) | 0 (0–0) | 178 (86–178) | 179 (176–182) |
| MySQL 실행 중 스레드 | 2 (2–3) | 2 (2–3) | 3 (2–3) | 2 (2–2) |

요청 1건당 SQL 문은 MySQL이 받은 전체 문장 수를 앱이 받은 요청 수로 나눈 값이라 트랜잭션 시작·종료 문장을 포함합니다.
