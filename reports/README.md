# 부하 테스트 보고서

측정이 끝난 API의 보고서만 올립니다.

- 스크립트와 실행 방법, 환경 만드는 방법은 [README.md](../README.md)에 있습니다.
- 보고서는 측정한 환경별로 나눕니다. 로컬은 `local/`, dev.imhungry.click은 `dev/`입니다. 그 아래 폴더 이름은 스크립트 폴더 이름과 같게 만듭니다(`recipes-popular/`, `orders/`, `cart-add/` …). 환경이 다른 숫자는 섞지 않습니다.
- 로컬 숫자는 dev.imhungry.click과 같은 서버 구성(앱, 데이터, 검색)에 모니터링 서버를 추가한 환경에서 측정한 값이고, 같은 조건의 개선 전후 비교에만 씁니다. dev.imhungry.click 숫자는 집 회선에서 인터넷을 거쳐 보낸 값이라 응답 시간에 그 왕복 시간이 들어 있습니다.
- dev.imhungry.click 보고서는 k6 결과만으로 씁니다. 서버 지표(CPU 사용률, CPU 크레딧)는 넣지 않고 원인 분석도 하지 않습니다. 측정 시각(시작과 끝)은 적어 둡니다.
- k6 결과 화면(HTML)은 `tools/share-html.py`로 로컬 경로를 지운 사본을 보고서 옆에 함께 둡니다(로컬, dev.imhungry.click 모두). 보고서의 근거 자료에서 회차 순서대로 링크합니다.
- 가상 사용자를 올리는 측정은 k6 요약(전체 구간 합계)만 쓰지 않고 `tools/timeline.py`로 10초 단위 표를 함께 넣습니다.
- 각 보고서는 대상, 측정 조건(그 API에만 해당하는 데이터와 검색어 등), 부하 조건, 실행 방법, 결과 순서입니다. 캐시 적용 전후 비교가 있는 보고서에만 해석(관찰한 것과 의심되는 원인을 구분)을 붙이고, 다음에 할 것은 개선을 맡은 도메인의 보고서에만 씁니다. 수치는 측정한 값만 적고 측정하지 않은 것은 "미측정"으로 적습니다.

보고서 목록과 핵심 결과는 [README.md의 결과](../README.md#4-결과)에 있습니다.
