## 1. 대상

[ramp-baseline.md](ramp-baseline.md)와 같은 흐름입니다. 로그인한 회원이 장바구니에서 주문하고, 주문 확인 화면에서 결제하지 않고 나갑니다.

| 순서 | 요청 | 응답 | 내용 |
|---|---|---|---|
| 1 | GET /api/members/me | 200 | 장바구니 화면의 로그인 확인 |
| 2 | GET /api/cart-items | 200 | 장바구니 목록 |
| 3 | POST /api/orders | 201 | 주문하기 |
| 4 | GET /api/orders/{orderId}/checkout | 200 | 주문 확인 화면 |
| 5 | PATCH /api/orders/{orderId}/cancel | 200 | 나가기 |

## 2. 측정 조건

| 항목 | 기준선 | 이번 |
|---|---|---|
| 테스트 상품 | 2개(29, 30), 재고 각 2,000개 | 50개(31–80), 재고 각 100,000개, 행사 없음 |
| 주문 한 건에 담는 상품 | 두 상품 모두 1개씩 | 회원에게 배정된 상품 1개 |
| 상품 배정 | 모든 회원이 같은 두 상품 | 회원마다 50개 중 1개를 무작위로 고정 배정(시드 42). 상품마다 9–29명 |

- 테스트 회원 1,000명, 가상 사용자 1명이 회원 1명을 맡는 것, 반복 사이 1–3초 쉬는 것, 단계와 자동 중단 기준은 기준선과 같습니다.
- 주문 한 건의 상품 수가 기준선은 2개, 이번은 1개입니다. 그래서 이 비교의 차이에는 상품을 나눈 효과와 주문 한 건이 가벼워진 효과가 함께 들어 있습니다.

## 3. 부하 조건

| 항목 | 값 |
|---|---|
| 가상 사용자 | 0 → 100명(30초) → 500명(60초) → 1,000명(60초) → 1,000명 유지(120초) → 0명(30초) |
| 자동 중단 | 실패율 5% 초과 또는 p95 2초 초과 (시작 30초 뒤부터, 시작부터 쌓인 전체 요청 기준) |
| 반복 | 1회 |

## 4. 실행 방법

```bash
BASE_URL=https://dev.imhungry.click k6 run -e COUNT=50 scenarios/dev-prep/test-products.js   # ADMIN_EMAIL, ADMIN_PASSWORD 환경변수 필요

python3 tools/timeline.py results/dev/order-ramp-spread-<시각>.html
```
