- 환경: `https://dev.imhungry.click`, 앱 서버 t4g.small 1대. k6는 집 회선에서 인터넷을 거쳐 보냈으므로 응답 시간에 그 왕복 시간이 들어 있습니다. 로컬 보고서([../../local/products/baseline.md](../../local/products/baseline.md))와 숫자를 섞지 않습니다.

## 2. 측정 조건

- dev.imhungry.click 상품 17개, 페이지 1 또는 2를 무작위로 골랐습니다.
- 가상 사용자(VU) 1명이 목록을 보고 1–3초 쉰 뒤 다시 보는 것을 반복합니다(가상 사용자 수 고정 방식). 실제 사용자 수와 같지 않습니다. 1,000명이면 이론상 초당 약 476건입니다(평균 반복 시간 2.1초).
- 측정 전에 10명, 30초로 먼저 돌려 확인했습니다(p95 84ms, 실패 0%).

## 3. 부하 조건

| 항목 | 값 |
|---|---|
| 가상 사용자 | 0 → 100명(30초) → 500명(60초) → 1,000명(60초) → 1,000명 유지(120초) → 0명(30초) |
| 자동 중단 | 실패율 5% 초과 또는 p95 2초 초과 (시작 30초 뒤부터) |
| 반복 | 1회 |

## 4. 실행 방법

```bash
BASE_URL=https://dev.imhungry.click ./tools/run.sh scenarios/products/products-list.js
python3 tools/timeline.py results/dev/products-list-<시각>.html
```

## 5. 결과

자동 중단 없이 끝났고 95,359건 모두 200이었습니다(실패 0%). 전체 구간을 합친 값은 p50 43ms, p95 393ms, p99 785ms, 최대 1.78초입니다. 이 값은 아래 두 구간이 섞인 값이라 시간대별로 봐야 합니다.

### 5-1. 구간별 요약

| 구간 | 가상 사용자 | 초당 요청 | p50 | p95 | p99 |
|---|---|---|---|---|---|
| 0–140초 | 30–907 | 9–433 | 21–29ms | 33–159ms | 55–326ms |
| 150–170초 | 991–1,000 | 436–463 | 82–90ms | 774–798ms | 867–986ms |
| 180–270초 (1,000명 유지) | 1,000 | 446–480 | 54–128ms | 159–820ms | 213–1,043ms |

- 가상 사용자 약 900명(초당 약 430건)까지는 p50이 21–28ms로 거의 변하지 않았습니다.
- 1,000명에 닿은 뒤 p50이 80–90ms대로 올랐고 p95가 159–820ms 사이에서 출렁였습니다. 초당 요청은 이론값(약 476건) 근처까지 따라갔습니다.
- 내리는 구간에서 바로 20ms대로 돌아왔습니다.
