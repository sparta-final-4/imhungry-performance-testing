## 1. 질문, 상황, 기준

- 질문: 번개 드롭 알림을 받은 회원 전체가 같은 순간 메인 화면을 열어도 지금 뜨는 할인이 늦지 않게 뜨는가.
- 상황: 1,000명이 같은 순간 한 번씩 요청합니다. 로그인 안 함(앱을 처음 여는 사람)과 로그인 함(회원) 두 조건입니다.
- 기준: 회차마다 p95가 0.67초 이하이고 실패가 0건이면 통과입니다.

## 2. 대상과 측정 조건

| 항목 | 내용 |
|---|---|
| API | GET /api/sales/popular |
| 캐시 | 결과에 10초 캐시가 걸려 있고 그대로 둠 |

| 보내는 방식 | 준비를 마친 뒤 정해 둔 같은 시각에 1,000명이 한 번씩 보냄 |

| 첫 요청 | HTTPS 연결 수립이 들어감(`PREWARM=0`) |

## 5. 분석

- 같은 API, 같은 캐시, 같은 1,000명인데 로그인 안 함은 p95 133–261ms로 통과했고 로그인 함은 1,029–1,197ms로 기준의 1.5–1.8배였습니다. 가운데 값은 174ms 대 1,147ms로 약 6.6배 차이입니다(계산).
- 로그인 함은 p50도 572–658ms로, 요청의 절반이 이미 기준에 가깝습니다. 로그인 안 함의 p50은 31–106ms입니다.
- 로그인 안 함은 p95가 기준 아래인데 최대가 610–1,380ms로 회차마다 달랐습니다. 소수의 요청이 느렸습니다.
- 예열 회차는 두 조건 모두 본 측정보다 느렸습니다(로그인 안 함 p95 587ms, 로그인 함 1,544ms).
- 두 조건의 차이가 어디서 오는지는 확인하지 않았습니다. 로그인 함 요청만 거치는 인증 처리가 원인일 가능성이 있지만, 이 보고서의 숫자로는 말할 수 없습니다(추정).
