# 이번 달 많이 만든 레시피 부하 테스트: dev.imhungry.click 기준선 (가상 사용자(VU) 1,000명)

상태: 초안 · 측정 시각: 2026-11-05 18:08:28–18:13:31 · 도메인 담당자: 이현정

- 환경: `https://dev.imhungry.click`. k6는 집 회선에서 인터넷을 거쳐 보냈으므로 응답 시간에 그 왕복 시간이 들어 있습니다.
- 근거 자료
  - 스크립트: [`scenarios/recipes-popular/recipes-popular-ramp.js`](../../../scenarios/recipes-popular/recipes-popular-ramp.js)
  - k6 결과 화면: [`recipes-popular-ramp-20261105-180828.html`](recipes-popular-ramp-20261105-180828.html) (내려받아 브라우저로 엽니다)
  - 10초 단위 표: [`tools/timeline.py`](../../../tools/timeline.py)로 만들었습니다
- 담당자가 정한 조건(동시 사용자 20명)으로 측정한 결과는 [baseline.md](baseline.md)에 있습니다.
- 미정 항목: 합격선, 측정한 앱 커밋 해시.

## 1. 대상

| 항목 | 내용 |
|---|---|
| API | GET /api/recipes/popular?size=6 |
| 화면 | 메인 화면 이번 달 많이 만든 레시피 |
| 로그인 | 필요 없음 |

이 API 하나만 부릅니다. 화면이 함께 보내는 로그인 확인 요청은 보내지 않았습니다. 화면 전체 흐름은 메인 화면 보고서([../main/baseline.md](../main/baseline.md))에 있습니다.

## 2. 측정 조건

- dev.imhungry.click의 데이터를 그대로 썼습니다.
- 이 API는 Redis 캐시(24시간)가 걸려 있고, dev.imhungry.click은 공용 서버라 캐시를 비우지 않았습니다. 그래서 이 측정은 **캐시 적중 경로**만 측정한 값입니다.
- 가상 사용자(VU) 1명이 이 API를 부르고 1–3초 쉰 뒤 다시 부르는 것을 반복합니다(가상 사용자 수 고정 방식). 실제 사용자 수와 같지 않습니다. 1,000명이면 이론상 초당 약 500건입니다.
- 측정 전에 10명, 30초로 먼저 돌려 확인했습니다(127건, p95 20ms, 실패 0%).

## 3. 부하 조건

| 항목 | 값 |
|---|---|
| 가상 사용자 | 0 → 100명(30초) → 500명(60초) → 1,000명(60초) → 1,000명 유지(120초) → 0명(30초) |
| 자동 중단 | 실패율 5% 초과 또는 p95 2초 초과 (시작 30초 뒤부터, 시작부터 쌓인 전체 요청 기준) |
| 반복 | 1회 |

## 4. 실행 방법

```bash
BASE_URL=https://dev.imhungry.click ./tools/run.sh scenarios/recipes-popular/recipes-popular-ramp.js
python3 tools/timeline.py results/dev/recipes-popular-ramp-<시각>.html
```

## 5. 결과

자동 중단 없이 끝났고 99,548건 모두 200이었습니다(실패 0%). 전체 구간을 합친 값은 p50 11.66ms, p95 18.5ms, p99 79.12ms, 최대 489.89ms입니다.

### 5-1. 구간별 요약

| 구간 | 가상 사용자 | 초당 요청 | p50 | p95 | p99 |
|---|---|---|---|---|---|
| 0–150초 | 33–990 | 10–478 | 11–13ms | 16–25ms | 18–78ms |
| 160–270초 (1,000명 유지) | 1,000 | 488–502 | 12ms | 16–211ms | 24–359ms |
| 280–300초 (내리는 구간) | 732–65 | 411–82 | 11–12ms | 15–91ms | 26–241ms |

- 가상 사용자 1,000명까지 p50이 11–13ms로 변하지 않았습니다.
- 초당 요청은 1,000명에서 488–502건으로 이론값(약 500건)을 따라갔습니다.
- 1,000명을 유지하는 동안 p95는 대부분 16–19ms였고, 160초(80ms)와 220초(211ms)에 한 번씩 올랐다가 다음 구간에 돌아왔습니다.
