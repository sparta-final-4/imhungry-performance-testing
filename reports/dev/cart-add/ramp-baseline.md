# 장바구니 담기·빼기 부하 테스트: dev.imhungry.click 기준선 (가상 사용자(VU) 1,000명 목표)

상태: 초안 · 측정 시각: 2026-11-05 23:29:21–23:31:22 (준비 단계 23:28:07부터) · 도메인 담당자: 장준혁

- 환경: `https://dev.imhungry.click`. k6는 집 회선에서 인터넷을 거쳐 보냈으므로 응답 시간에 그 왕복 시간이 들어 있습니다.
- 근거 자료
  - 스크립트: [`scenarios/cart-add/cart-add-ramp.js`](../../../scenarios/cart-add/cart-add-ramp.js)
  - 테스트 회원 준비: [`scenarios/dev-prep/members.js`](../../../scenarios/dev-prep/members.js)
  - k6 결과 화면: [`cart-add-ramp-20261105-232807.html`](cart-add-ramp-20261105-232807.html) (내려받아 브라우저로 엽니다)
  - 10초 단위 표: [`tools/timeline.py`](../../../tools/timeline.py)로 만들었습니다
  - API별 p95: 측정 중에 k6를 실행한 컴퓨터의 로컬 Prometheus로 보낸 요청별 값에서 뽑았습니다
- 미정 항목: 합격선, 측정한 앱 커밋 해시.

## 1. 대상

로그인한 회원이 상품을 장바구니에 담고, 장바구니 화면에서 그 상품을 빼는 흐름입니다.

| 순서 | 요청 | 응답 | 내용 |
|---|---|---|---|
| 1 | POST /api/cart-items | 201 | 담기 |
| 2 | GET /api/members/me | 200 | 장바구니 화면의 로그인 확인 |
| 3 | GET /api/cart-items | 200 | 장바구니 목록 |
| 4 | DELETE /api/cart-items?cartItemIds={id} | 200 | 선택 삭제 |

- 매번 빼므로 담기는 늘 새 장바구니 항목을 저장하는 경로입니다. 장바구니가 커지지 않습니다.

## 2. 측정 조건

- 테스트 회원 1,000명을 썼습니다. 가상 사용자 1명이 회원 1명을 맡아, 같은 회원의 장바구니를 여러 가상 사용자가 동시에 건드리지 않습니다.
- 담는 상품은 행사가 없는 상품 18입니다. 회원 장바구니에는 상품 16·17·19·29·30이 1개씩 미리 들어 있습니다.
- 가상 사용자(VU) 1명이 위 흐름을 한 번 하고 1–3초 쉰 뒤 다시 하는 것을 반복합니다(가상 사용자 수 고정 방식). 실제 사용자 수와 같지 않습니다. 한 번에 요청 4건이므로 1,000명이면 이론상 초당 약 1,800건입니다.
- 측정 전에 준비 단계에서 1,000명이 로그인했습니다(약 1분 15초). 이 로그인 요청(p95 387ms)도 자동 중단 기준인 전체 p95에 들어갑니다.
- 측정 전에 10명, 30초로 먼저 돌려 확인했습니다(519건, p95 56ms, 실패 0%).

## 3. 부하 조건

| 항목 | 값 |
|---|---|
| 가상 사용자 | 0 → 100명(30초) → 500명(60초) → 1,000명(60초) → 1,000명 유지(120초) → 0명(30초) |
| 자동 중단 | 실패율 5% 초과 또는 p95 2초 초과 (시작 30초 뒤부터, 시작부터 쌓인 전체 요청 기준) |
| 반복 | 1회 |

## 4. 실행 방법

```bash
BASE_URL=https://dev.imhungry.click ./tools/run.sh scenarios/cart-add/cart-add-ramp.js
python3 tools/timeline.py results/dev/cart-add-ramp-<시각>.html
```

## 5. 결과

측정 2분 8초, 가상 사용자 약 810명에서 p95가 2초를 넘어 자동 중단됐습니다. 흐름의 요청 33,623건이 모두 기대한 응답이었습니다(실패 0%). 준비 단계를 합친 전체 값은 p50 589ms, p95 2.02초, p99 2.47초, 최대 4.27초입니다.

### 5-1. 구간별 요약

| 구간 | 가상 사용자 | 초당 요청 | p50 | p95 |
|---|---|---|---|---|
| 20–50초 | 42–184 | 59–296 | 29–43ms | 38–96ms |
| 60–90초 | 251–451 | 285–330 | 194–778ms | 863–1,448ms |
| 100–130초 | 522–772 | 312–335 | 1,017–1,678ms | 1,822–2,409ms |

- 가상 사용자 약 180명(초당 약 300건)까지는 p50이 29–43ms였습니다.
- 초당 요청은 가상 사용자 약 250명(60초)부터 285–335건에서 더 늘지 않았습니다. 가상 사용자가 늘어난 만큼 응답 시간이 길어졌습니다.
- 10초 구간은 첫 구간에 준비 단계의 마지막 요청이 섞여 있습니다.
